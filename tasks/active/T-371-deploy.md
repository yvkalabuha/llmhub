### Находки
- **REV2-1 major** — `src/llmhub/local_inference/client.py:166` (`_headers`) и `:236` (`probe`). Ключ перечитывается только при `_api_key is None` или после 401 у **chat**. llama-server с `--api-key` закрывает `/slots`, а в `config.example.yaml` стоит `probe: slots`. После ротации ключа каждая фоновая проба получает 401 → `stats.on_probe` ставит `available=False` → router больше не шлёт chat на этот бэкенд → повторное чтение ключа после 401 не происходит никогда. Локальный бэкенд лежит до `docker restart llmhub-api`. Исправление: в `probe()`/`_get` при 401 и `_may_reload()` перечитать ключ и повторить GET один раз (как в chat). Тест: `test_probe_401_after_key_rotation_rereads_key` (xfail).
- **REV2-2 low** — `client.py:251-253`. `/slots` с ответом 200 и JSON не-списком (`{"error":…}`, строка) считается здоровым, а `total_slots` равен числу ключей или символов. Нужно `isinstance(slots, list)`, иначе `ProbeResult(False, …)`. Тест: `test_slots_non_list_json_is_not_healthy` (xfail, 2 параметра).
- **REV2-3 medium** — `scripts/e2e_mock.py:236-243` (`phase_kill`) и `_live_instances`. Проверка «0 ресурсов ≤ 60 с» смотрит только на `/admin/status` → `live_instance`, а тот исключает `PENDING_DELETE`/`LEAKED` (`LIVE_IN_INDEX`). Ответ `/admin/kill` (`completed`, `remaining`) не проверяется, инциденты `kill_incomplete` тоже. Если destroy не подтвердился, фаза всё равно отчитывается `ok`. Значит, критерий приёмки «kill: 0 ресурсов ≤ 60 с» доказывается слабее, чем заявлено. Исправление: требовать `completed is True and remaining == []` и отсутствие `kill_incomplete` (лучше дополнительно сверить с reaper `--once`/`list_owned` Mock). Тест: `test_e2e_kill_fails_when_kill_report_has_remaining_resources` (xfail).
- **REV2-4 low** — `src/llmhub/api_gateway/submission.py:95-118` + `task_queue/queue.py:105-112`. Повтор с `Idempotency-Key` проваленной retryable-задачи (`retry_failed`) проходит мимо лимита: `_check_client_limit` видит ключ в `jobs` и пропускает, а `submit` снимает ключ со старой задачи и создаёт **новую**. Проверено: при `max_active_jobs=2` получается 3 активные задачи. Перерасход ограничен числом таких ключей, но формулировка integration.md «повтор под лимит не попадает» верна только для живых и завершённых задач. Исправление: пропускать лимит, только если найденная по ключу задача не `failed`+retryable. Тест: `test_idem_retry_of_failed_job_is_limited` (xfail).
- **REV2-5 low** — `src/llmhub/persistence/backup.py:72-86`. Копия остаётся в режиме WAL: online backup переносит байты заголовка 18–19 = 2. Если открыть её для осмотра (`sqlite3 backup/state-….db`, ro), рядом появятся `-wal`/`-shm`, а ротация (`glob state-*.db`) их не удаляет. Сама копия консистентна. Предложение: `out.execute("PRAGMA journal_mode=DELETE")` перед `integrity_check`.
